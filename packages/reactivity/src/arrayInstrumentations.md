# Array Instrumentations (数组插桩)

`packages/reactivity/src/arrayInstrumentations.ts` 文件包含了 Vue 3 响应式系统中针对数组方法的特殊处理逻辑（插桩）。

由于 JavaScript `Proxy` 的限制以及数组操作的特殊性，直接拦截数组操作可能会导致一些问题，例如：
1.  **无限循环**：某些改变数组长度的方法（如 `push`）会读取 `length` 属性，如果此时正在进行依赖收集，可能会导致无限递归。
2.  **身份一致性**：用户期望在响应式数组中查找原始对象（或在原始数组中查找响应式对象）时能正确工作。
3.  **响应式转换**：在遍历数组时，需要确保获取到的元素也是响应式的。

为了解决这些问题，Vue 重写了部分数组方法。

## 核心辅助函数

### `reactiveReadArray`
- **功能**：追踪数组迭代操作。
- **逻辑**：
  - 如果输入是响应式的，返回一个包含响应式值的克隆原始数组。
  - 如果输入是非响应式或浅层响应式的，返回原始数组。
- **用途**：用于 `concat`, `join`, `toReversed` 等需要读取整个数组的方法。

### `shallowReadArray`
- **功能**：追踪数组迭代操作，但始终返回原始数组。
- **用途**：用于内部需要追踪但不进行深层响应式转换的场景。

### `toWrapped`
- **功能**：将数组元素转换为响应式或只读对象。
- **逻辑**：根据目标数组是否为只读/响应式，决定将元素转换为 `readonly` 或 `reactive`。

## 插桩方法分类

### 1. 迭代器方法 (`Symbol.iterator`, `entries`, `values`)
- **问题**：直接迭代代理对象可能无法获取到响应式的元素，或者依赖收集不完整。
- **解决**：重写迭代器生成逻辑，在 `next()` 调用时建立 `ARRAY_ITERATE` 依赖，并将返回的值通过 `toWrapped` 转换为响应式对象。

### 2. 查找方法 (`includes`, `indexOf`, `lastIndexOf`)
- **问题**：用户可能使用原始对象在响应式数组中查找，或者使用响应式对象在原始数组中查找。
- **解决**：
  1.  首先在当前数组（可能是代理）上尝试查找。
  2.  如果未找到，并且参数是响应式对象，则将其转换为原始对象再次查找。
  3.  过程中会进行依赖收集。

### 3. 变异方法 (`push`, `pop`, `shift`, `unshift`, `splice`)
- **问题**：这些方法会修改数组并可能更新 `length` 属性。在某些情况下（如在 `watchEffect` 中调用 `push`），读取 `length` 会导致依赖收集，进而触发副作用重新执行，导致无限循环。
- **解决**：在执行这些方法时，**暂停依赖收集** (`pauseTracking`)，执行原始方法，然后再恢复 (`resetTracking`)。

### 4. 遍历与变换方法 (`forEach`, `map`, `filter`, `every`, `some`, `find`, `findIndex`, `findLast`, `findLastIndex`)
- **问题**：回调函数中的参数需要是响应式的，且 `this` 指向需要正确。
- **解决**：
  - 使用 `apply` 辅助函数。
  - 追踪数组迭代。
  - 包装回调函数，确保回调接收到的参数经过 `toWrapped` 处理（即是响应式的）。
  - 处理 `thisArg`。

### 5. Reduce 方法 (`reduce`, `reduceRight`)
- **逻辑**：与遍历方法类似，重写了回调函数的处理逻辑，确保累加器和当前项的处理符合响应式预期。

## 关键实现细节

### `apply` 函数
这是一个通用的高阶函数，用于插桩 `forEach`, `map` 等方法。它负责：
1.  调用 `shallowReadArray` 进行追踪。
2.  检查是否需要包装回调函数（非浅层响应式时）。
3.  处理用户自定义扩展数组的情况（参数未知时跳过特殊处理）。
4.  执行原始方法。

### `noTracking` 函数
用于包装变异方法（如 `push`）。它通过 `pauseTracking()` 和 `resetTracking()` 包裹原始方法的执行，确保在方法执行期间不会收集不必要的依赖。
